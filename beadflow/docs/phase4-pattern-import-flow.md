# 图纸上传、OCR 与复核草稿主流程

更新时间：2026-07-22

## 用户流程

1. 用户选择一张 JPEG、PNG 或 WebP 图纸并填写名称；
2. 默认识别图片纵向 70%–99% 的底部图例区域，后续界面可让用户调整；
3. API 调用正式 `/pattern-legend/recognize` OCR 接口；
4. OCR 色号必须映射到已验证的 MARD 221 色卡；
5. 原图保存至用户自己的私有 `pattern-images` 存储桶路径；
6. 数据库在一个事务中创建图片资产、资料卡和待复核材料草稿；
7. 返回短期签名原图地址、证据框、识别置信度、冲突列表和复核草稿；
8. 用户人工确认后才会产生正式材料版本，才可参与库存计算和推荐。

## 防重复设计

API 对原图字节计算 SHA-256。存储路径固定为：

`{userId}/patterns/{sha256}/source`

数据库对 `(user_id, sha256)` 保持唯一，并锁定资产后检查是否已有未归档资料卡。相同账户重复上传完全相同的文件时返回原资料卡，不重复创建草稿，也不会造成重复库存统计。

## 失败边界

- OCR 在任何云端写入之前执行；OCR 失败不会创建资料卡；
- 未知色号在存储与数据库写入前拒绝；
- 数据库函数以单事务写入资产、资料卡、材料草稿和审计日志，不会留下半张资料卡；
- 存储成功但数据库调用失败时，最多留下不可见的哈希路径对象，不会产生可参与业务的资料卡；
- 上传和导入不会扣减、预留或修改库存；
- OCR 识别为 0 项仍可保留为空的待复核草稿，允许用户人工补充，不伪造色号。

## 隐私与权限

- `pattern-images` 是私有桶；
- 存储策略只允许访问以当前用户 ID 开头的路径；
- `create_pattern_card_from_ocr` 与 `get_pattern_card_source` 都从 `auth.uid()` 获取用户身份；
- 客户端不能指定可信用户 ID；
- 原图读取通过 10 分钟有效的签名地址，不返回内部永久公开链接。

## 测试

API 测试使用 3.2MB、21 色、包含低置信度项和冲突色号的图例结果，验证：

- OCR 裁剪参数与声明总数传递；
- 21 个材料项全部保持待人工确认；
- SHA-256 与色号映射正确；
- 重复上传返回已有资料卡；
- 未知 MARD 色号在写库前拒绝；
- 非法裁剪在 OCR 前拒绝；
- 私有上传、原子 RPC 和签名预览请求链；
- 页面重新进入后可以重新获取短期原图地址。

## 云端迁移

`202607220004_pattern_card_import.sql` 将新增私有存储桶、按用户隔离的存储策略，以及两个 RPC：

- `create_pattern_card_from_ocr(...)`
- `get_pattern_card_source(uuid)`

迁移必须先预演，并在用户明确授权后才可部署。
