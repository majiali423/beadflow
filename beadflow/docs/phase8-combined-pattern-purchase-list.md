# Phase 8：多图合并补豆清单

## 用户目标

用户准备连续制作多张图纸时，不应逐张采购并重复计算同一色号。图纸库允许选择 1–20 张已经人工确认材料的图纸，先合并相同 MARD 色号的需求，再与当前个人库存比较一次。

## 已实现

- 图纸库中只有“已确认”图纸可加入合并补豆，待复核图纸不会进入计算。
- `POST /api/pattern-cards/combined-purchase-list` 接收明确的图纸 ID 列表；接口只读，不预留或扣减库存。
- 服务端从当前用户的正式材料版本读取数据，不信任客户端提交的数量。
- 相同色号跨图纸累加后再减库存，避免重复使用同一批库存。
- 返回总用量、合并色数、缺口、库存估算提示、按缺口排序的明细、复制文本和 CSV。
- 若有重复 ID、不存在的图纸或尚未确认的图纸，整次请求失败，不会静默跳过。
- 选择变化后旧结果立即清空，避免把上一组图纸的清单误当成当前结果。

## 验收覆盖

- API 真实规模组合：3 张图纸、1140 颗需求、重叠色号合并为 190 颗后与 120 颗库存比较，得到 70 颗缺口；总缺口 970 颗。
- 页面真实规模组合：3 张图纸、4516 颗、跨 21+ 色数据，展示 684 颗缺口并可复制来源完整的合并清单。
- 重复选择和未确认图纸均有显式错误。
- 自动测试确认没有调用库存事务或批量写入。

## 当前边界

- 这是即时采购测算，不是库存预留。之后库存发生变化时，应重新点击“合并计算补豆”。
- 当前不会保存临时选择，刷新页面后需重新选择，避免产生用户误以为已锁定库存的错觉。
- 无需新增 Supabase 表或迁移，现有已登录用户与 RLS 数据边界保持不变。
