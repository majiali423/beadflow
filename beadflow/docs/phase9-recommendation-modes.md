# Phase 9：三种可解释的库存推荐

## 用户目标

同一份库存下，“马上找一张能做的图”和“尽量消耗囤积色”不是同一个需求。图纸库现在让用户明确选择推荐目标，排序依据均为可验证的库存数字，不使用黑盒模型。

## 三种模式

### 现在就能做

- 严格排除任何存在缺口的图纸。
- 在可制作图纸中，优先制作后仍远离低库存提醒线的项目。
- 展示“所有色号库存都够”，不会把覆盖率较高但仍缺豆的图混入结果。

### 补豆最少

- 先按缺少总颗数升序。
- 总缺口相同时，按缺少色号数量升序。
- 再考虑制作后触碰低库存提醒线的色号数量。
- 推荐理由直接显示“补多少颗、涉及几个色号”。

### 优先消耗囤积色

- 高库存定义为当前数量中高于该色低库存提醒线的部分。
- 只计算本图实际能消耗的高库存部分，不把提醒线以下的数量当作囤积。
- 优先库存足够制作的图，再按可消耗囤积豆颗数排序。
- 页面展示主要消耗的 MARD 色号及颗数，并提示会触碰提醒线的风险。

## 工程边界

- 只读取当前用户的已确认图纸、个人库存及提醒线。
- 切换模式不会写入、预留或扣减库存。
- 不联网抓取第三方图纸，不训练推荐模型。
- 排序完全确定，同一数据和模式会得到相同结果。
- 库存改变后重新请求推荐，不缓存过期的推荐结果。

## 验收覆盖

- 真实规模算法场景包含 620 颗囤积色图、90 颗紧库存图和 300 颗缺料图。
- “现在就能做”只保留两张库存足够的图。
- “补豆最少”明确识别 20 颗、1 色的缺口。
- “优先消耗囤积色”识别 620 颗可消耗库存，并返回 B14 400 颗、C6 220 颗式的色号明细。
- 页面自动测试完成三种模式连续切换，验证请求参数、理由和具体色号展示。
